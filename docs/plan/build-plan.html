AERIAL CONCERN · DEADLINE VS DEPTH

"Phased build with full docs and design reviews at every milestone" and "done before 6 October" pull against each other. That's roughly two and a half days. A full Phased pipeline (UX map, every screen documented, four independent reviewers at each milestone) would eat a day on its own.

What I propose instead keeps the parts that prevent rework and drops the ceremony: one architecture doc, a decision log, the schema as SQL, a design brief with tokens, and one prompt file per phase. Design reviews happen at two gates (the card, and the finished app), not after every phase. Everything P2 waits until after the 6th. If you'd rather keep the full ceremony, scope has to shrink instead (moderation and search would go first).

D-003 IN DETAIL · GOOGLE + GITHUB

How sign-up and the repo picker work

  1. Continue with Google. Creates the account. The Google email is where approval notices and updates go.
  2. Connect GitHub. Links a second identity to the same account. This also proves the GitHub link on the card belongs to that person, so the card can show it as verified.
  3. Pick your repos. The browser lists the member's public repos straight from GitHub. They tick up to six, reorder them, and can rewrite the description or add a cover image.
  4. Saved as a copy. Picked repos are stored as project rows. Visitors never wait on GitHub, and a "refresh from GitHub" button updates the copy when the member wants.
CATCH 1 · SETUP

Linking a second sign-in to one account is a beta feature in Supabase and has to be switched on in the auth settings. On Google's side the OAuth app must be set to In production. In Testing mode only listed test users can sign in. With only email and profile access it doesn't need Google's full verification review.

CATCH 2 · EMAIL

Supabase sends sign-in emails, not updates. Sending "your card was approved" needs a mail service. Resend's free tier needs a domain you own. Gmail's SMTP with an app password works free with no domain. Members also need an opt-in checkbox for update emails. For the 6th, I'd store the opt-in and send the first emails after launch.

ALTERNATIVE · ONE LINE

GitHub sign-in alone also returns a verified email, which would remove the Google setup and the beta linking feature. You chose both, so I'm building both. Say the word if you want the simpler path.

PRIVATE REPOS · NOT IN SCOPE

Public repos need no GitHub permission at all. Private repos would mean storing a GitHub token per member, which Supabase doesn't refresh for us. Private and school work can go in through the manual form (D-007).

SUGGESTIONS

Things I'd add or change

P1 items fit in the three days. P2 items wait until after the 6th.

P1 · build order

Build the card and carousel first, on sample data

The spec puts auth before the card, but it also says the card interaction wins every tie. Building the riskiest, most visible part first, behind a data service with a fixture file, means the demo looks right from week one. Supabase then slots in behind the same service.

P1 · empty state

Generated pixel avatar when there's no photo

Like the one on the probe: a symmetric 10×10 sprite drawn from the username. No upload needed to look finished, and it fits the world better than a grey silhouette.

P1 · QR

Tap the QR to go full screen

A 70px code on a phone is hard to scan from another phone. Tapping it opens a large SCAN ME screen, which is how it'll actually get used at booths and meetings.

P1 · search

Filter in the browser, not the database

An org has hundreds of approved cards at most. Load them once and filter in memory. Instant results, no search index, and it works offline from the PWA cache.

P2 · juice

Synthesized sound, off by default

Short square-wave blips for flip and snap, generated with the Web Audio API. No audio files, so there are no licensing questions and nothing extra to download.

P2 · events

Booth mode

A full-screen carousel that auto-advances, for org fairs and recruitment week. Mostly reuses the carousel.

P2 · sharing

Link previews on Messenger

A single-page app shows the same generic preview for every member link. Per-member previews need a small edge function that renders the card as an image. Worth it if sharing in group chats matters to you.

P2 · print

Export card as PNG

For social posts and printed lanyards. The card is already a fixed-size component, so rendering it to an image is cheap.
